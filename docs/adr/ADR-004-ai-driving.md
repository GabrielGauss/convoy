# ADR-004 — AI driving

- **Status:** Proposed (architect, ARCH-001, 2026-10-11) · **Human owner/reviewer:** Gabriel or Lead Dev (A-01 is "GV or DEV" in the backlog); track paths: Narrative & Game Designer (T-01)
- **Serves:** A-01 (3 rivals, ≥ 90 % completion, ±15 % of a competent human, no rubber-banding), D-006 (AI is a core pillar after M1). **Proposes:** D-019.

## Context
- Rivals must drive **the same `VehicleController` through the same `IPilotCommandReceiver.SetPilotCommand(PilotCommand)`** a human uses — no cheating physics (A-01).
- Evidence: a scripted autopilot (used once via MCP during S-01 verification, not committed) completed `Sprint_01` start → Monolith with a **centreline polyline + lookahead steering + lateral lane offsets**: 5/5 checkpoints, 01:46 with 3 resets. Its weak spots were the boulder field and wrecks (obstacles).
- `Sprint_01`'s road is built from 295 objects `Road_0 … Road_294` placed **in driving order** ~3.7 m apart along the centreline — a ready-made path source.
- Packages: `com.unity.ai.navigation` (NavMesh) is installed; `com.unity.splines` is not.

## Options considered
| Path representation | + | − | Verdict |
|---|---|---|---|
| NavMesh agent | built-in pathing | NavMesh agents drive kinematically / ignore vehicle dynamics; no racing line; A-01 forbids it | **rejected** |
| Unity Splines package | nice in-editor authoring, smooth curves | new package (decision entry), API surface to learn, builders can't author in editor anyway | deferred |
| **Waypoint polyline** (ordered child `Transform`s) | zero packages, trivially generated by editor scripts (from `Road_N`) or placed by hand in T-01, pure maths testable in EditMode, proven by the S-01 autopilot | corners are piecewise-linear (handled by lookahead smoothing and curvature sampling over a span) | **chosen** |

If the ND later wants smoother authoring for T-01, a Splines adapter can *produce* the same `PolylinePath` by sampling the spline every 3–5 m; the driving brain does not change. Adopting the package needs its own decision entry.

## Decision

### Structure (`Convoy.AI`, references Core + Vehicle)
```
RacingLine (MonoBehaviour, per route)  ──builds once──►  PolylinePath (pure)
                                                          │
AiPilot (MonoBehaviour, per rival vehicle)                ▼
  FixedUpdate [order −50]:                         AiDriverBrain (pure)
   1. read VehicleController.State + 3 spherecasts ─► Step(in AiSensorFrame) ─► PilotCommand
   2. vehicle.SetPilotCommand(cmd)  ◄────────────────────────────────────────────┘
  IRecoveryPointProvider: pose on the path behind current progress
```
Everything that decides is pure C# (`PolylinePath`, `SpeedPlanner`, `LaneSelector`, `StuckDetector`, `AiDriverBrain`) and is tested in EditMode without physics. The MonoBehaviours only sense and forward.

### Path following (steering)
- **Progress:** project the car onto the polyline, searching only a window of segments around last tick's segment (`O(window)`, no allocation). If the projection's lateral offset exceeds `offPathResetDistance` (e.g. after a teleport), do one full search.
- **Lookahead (pure pursuit):** `lookahead = lookaheadBase + lookaheadPerSpeed × speed` (defaults 6 m + 0.5 s × v; at 40 m/s ≈ 26 m). Target = `PositionAt(progress + lookahead) + right(tangent) × laneOffset`.
- **Steer:** signed angle (on the ground plane) from the car's forward to the target, divided by the vehicle's *current* max steer angle — computed with the existing `VehicleMath.SteerAngle(1, maxSteerAngle, forwardSpeed, topSpeed, highSpeedSteerFactor)` so AI and physics agree — times `steerGain`, clamped to ±1.
- No handbrake use in M1 AI (simpler, stable). Boost on straights only (below).

### Speed planning for corners
Sample the path ahead every `planningStep` (5 m) up to `planningHorizon` (120 m). For each sample *i* at distance `dᵢ` ahead:
```
κᵢ        = heading change over curvatureSpan / curvatureSpan        (1/m)
v_cornerᵢ = sqrt(maxLateralAccel × cornerSpeedScale / max(κᵢ, 1e-4))
v_allowed = min over i of sqrt(v_cornerᵢ² + 2 × brakingDecel × dᵢ)   then min(topSpeed)
```
Throttle = `clamp((v_allowed − v) × throttleGain, −1, 1)` with a `coastBand` dead zone to avoid throttle chatter. Negative values brake (the vehicle's `ResolveLongitudinal` turns −throttle into braking while moving forward). Boost when `useBoost` and no sample within `boostClearDistance` (80 m) needs speed below `topSpeed`.

`cornerSpeedScale` is the main **competence knob** (0.85 steady … 0.98 aggressive). There is **no rubber-banding**: no code reads the player's position. If a catch-up is ever wanted it must be a profile field defaulting to 0 that only scales `v_allowed` — never physics — and needs a decision entry.

### Obstacle avoidance lanes
- Discrete lanes `{−1, 0, +1} × laneWidth` (2.5 m), limited to the route's `halfWidth` (per `RacingLine`, default 4 m).
- `AiPilot` casts three `Physics.SphereCast`s (radius 1 m, up to `obstacleCheckDistance` 25 m) along the path tangent from the car's nose at the three lane offsets, height 0.8 m. Hits on the car's own `Rigidbody` are ignored; hits whose normal · up > 0.5 are ignored (ramps/mounds are drivable, not obstacles). Other vehicles *are* obstacles.
- `LaneSelector` keeps the current lane while it's clear beyond `obstacleCheckDistance`, otherwise picks the clearest lane (ties → closest to centre); the actual offset moves toward the chosen lane at `laneChangeRate` m/s (no snapping). Cost: 3 casts × 3 rivals × 50 Hz = 450 casts/s — negligible.

### Recovery when stuck (uses V-02)
`StuckDetector` states: `Driving → Reversing → RequestReset`.
- Stuck = |speed| < `stuckSpeed` (1 m/s) for `stuckTime` (2.5 s) while the brain asks for throttle > 0.5.
- `Reversing` for `reverseTime` (1.5 s): throttle −1, steer mirrored. Up to `maxReverseAttempts` (2).
- Then `RequestReset`: one command with `Reset = true`. The vehicle's own `VehicleRecovery` applies cooldown and teleports to the pose from its `IRecoveryPointProvider`.
- *(A-01b)* The request is held (Neutral) while `VehicleState.RecoveryCooldown > 0` (passed in `AiSensorFrame.RecoveryCooldown`): auto-right also starts that cooldown, and a reset sent during it is silently dropped.
- *(A-01a, recorded in A-01b)* The reverse-attempt counter clears after `stuckTime` seconds of healthy driving (moving and making progress), so one rock early on doesn't use up the attempts for a different rock later.
- Also request reset when off-path > `offPathResetDistance` (25 m) or making negative progress for `wrongWayTime` (4 s). Upside-down is already handled by the vehicle's auto-right.
- **Recovery point:** `AiPilot` implements `IRecoveryPointProvider` with the path pose at `progress − recoveryBackoff` (10 m), facing the path tangent. It never returns a point *ahead* of progress, so a reset can't skip anything. When R-01 lands, R-01 may replace this with checkpoint-based recovery for all racers.

### Profiles: `AiDriverProfile` ScriptableObject
All numbers above live in `AiDriverProfile` (fields and defaults in `docs/specs/A-01-ai-driving.md`). Vehicle limits (max steer, top speed, steer falloff) are **read from the vehicle's `VehicleConfig`**, never duplicated. Three assets for M1: `AI_Steady` (0.85), `AI_Balanced` (0.92), `AI_Aggressive` (0.98). No randomness in M1 (deterministic runs make regressions visible); if variation is wanted later, use a seeded `System.Random` owned by the brain, never `UnityEngine.Random`.

### Start of race
Until R-01 provides a countdown, `AiPilot` has an optional `_waitForVehicle` (`VehicleController`): rivals hold `PilotCommand.Neutral` until that vehicle's horizontal speed exceeds 1.5 m/s (same rule `SprintController` uses to start the clock). R-01 replaces this with an explicit `Release()` call. Documented as temporary.

### Routes / forks (T-01)
One `RacingLine` per route. In A-01 each rival is assigned a route in the Inspector. Choosing a route at a fork by risk preference is **out of A-01 scope** (P1 follow-up once T-01's fork exists).

### Implementation notes (A-01b)
- `RacingLine` takes ordered child waypoints **or** `Configure(points, closed, halfWidth)` from code; open polylines of any shape are supported (TR-01 rival routes end at the crater; the brain brakes to a stop at the end).
- `AiPilot` casts its three lane spheres from the car's centre along the path tangent, one per *path* lane (same geometry as `LaneSelector`). Initial overlaps (distance 0) count only if the collider has a Rigidbody (a car beside us); static ones (ground on rough terrain) are ignored. It skips the step while the vehicle has not yet written its first `VehicleState`.
- `AiPilot.Configure(line, profile, waitFor)` wires a rival from code; editor scripts set the serialized fields. Profiler row: `Convoy.AiPilot.FixedUpdate`.

## Consequences
- + No new packages; reuses the proven autopilot idea; logic fully unit-testable.
- + AI and humans share the exact same physics and command path → no "AI cheats" complaints, and AI is a free regression driver for the Jackal.
- − Polyline corners need sensible spacing (3–15 m). Generated paths from `Road_N` use every 4th object (~15 m).
- − Three identical-looking Jackals; a presentation tint is a separate small task (not in A-01).
- − HUD/overlay currently pick `FindAnyObjectByType<VehicleController>()` and could pick a rival; A-01b fixes target resolution (skip vehicles with `AiPilot`).

## Proposed decisions
**D-019 — AI driving: waypoint polylines + pure-pursuit brain, same command path as humans** · Status: Proposed (architect) · Owner: Gabriel / Lead Dev
- AI rivals drive the standard vehicle via `IPilotCommandReceiver`; no NavMesh, no physics shortcuts, no rubber-banding in M1.
- Paths are `RacingLine` waypoint polylines (ordered child transforms), one per route; no Unity Splines package in M1 (adopting it later needs its own entry).
- Steering = lookahead pursuit with lane offsets; speed = curvature-limited planning with braking distance; stuck recovery = reverse, then V-02 reset to a path pose behind progress.
- All AI tunables in `AiDriverProfile` ScriptableObjects; vehicle limits come from `VehicleConfig`.
