# Spec LV-02 — Toxic mud surface zones

- **Human owner/reviewer:** Gabriel (vehicle feel, D-010) · **Builder agent:** vehicle-engineer · **Architecture:** ADR-001, ADR-003, ADR-006 § 1 (proposes D-027)
- **Split:** **LV-02a** surface data + pure modifiers + per-wheel cache + EditMode tests · **LV-02b** `SurfaceTag`, `VehicleController`/`VehicleState` edits, PlayMode surface + regression tests · **LV-02c** integration: mud profile, material, `MudPatch.prefab`, test patch in `Sandbox` (executed by the orchestrator)

## Objective
Toxic mud (D-021 Toxic Wastes: "−40 % traction and speed") as data-driven ground: each wheel whose suspension ray lands on a collider tagged with a `SurfaceProfile` gets scaled tyre friction, lateral grip, drive force, top speed and extra rolling resistance. Outside mud, handling must be **bit-identical** to today (Jackal PT-01 tuning, D-01 regression test). Nitro is not scaled — it is the counterplay to mud (D-027).

## Scope
`SurfaceKind`, `SurfaceProfile`, `SurfaceModifiers`, `WheelSurfaceCache`; `SurfaceTag`; seven listed `VehicleController` edits; `VehicleState.SurfaceWheels/Surface`; PlayMode tests; mud assets.

## Out of scope
Terrain splat-map surfaces (Unity Terrain layers), mud VFX/audio (later presentation task reads `VehicleState.Surface`), AI awareness of mud (A-02), other surfaces (ice, sand — same mechanism later), damage from toxic mud.

## Public interfaces
```csharp
// LV-02a — Assets/_Convoy/Scripts/Vehicle/SurfaceProfile.cs
namespace Convoy.Vehicle
{
    public enum SurfaceKind : byte { Default = 0, ToxicMud = 1 }

    [CreateAssetMenu(fileName = "SurfaceProfile", menuName = "Convoy/Surface Profile")]
    public sealed class SurfaceProfile : ScriptableObject
    {
        public SurfaceKind kind = SurfaceKind.ToxicMud;
        [Tooltip("Scales tireFriction (friction circle: max tyre force).")]
        [Range(0f, 2f)] public float frictionMultiplier = 0.6f;
        [Tooltip("Scales front/rear lateral grip.")]
        [Range(0f, 2f)] public float lateralGripMultiplier = 0.6f;
        [Tooltip("Scales engine drive force on this wheel.")]
        [Range(0f, 2f)] public float driveForceMultiplier = 0.6f;
        [Tooltip("Scales the speed where this wheel's drive fades out (nitro bonus is added unscaled).")]
        [Range(0.1f, 2f)] public float topSpeedMultiplier = 0.6f;
        [Tooltip("Scales rolling resistance (mud drag).")]
        [Range(0f, 10f)] public float rollingResistanceMultiplier = 3f;
    }

    /// Per-wheel multipliers. None = every field exactly 1f (x * 1f is exact in IEEE 754 → bit-identical handling).
    public readonly struct SurfaceModifiers
    {
        public readonly float Friction, LateralGrip, DriveForce, TopSpeed, RollingResistance;
        public readonly SurfaceKind Kind;
        public static SurfaceModifiers None { get; }
        public static SurfaceModifiers From(SurfaceProfile profile);   // null → None; NaN/negative field → 1f for that field
        public bool IsDefault { get; }                                  // Kind == Default
    }

    /// Remembers, per wheel, the last ground collider and the profile found on it so TryGetComponent runs only when a wheel
    /// moves onto a different collider. Stores the profile reference (not the numbers) so Inspector edits apply live, like VehicleConfig.
    public sealed class WheelSurfaceCache
    {
        public WheelSurfaceCache(int wheelCount);
        public bool TryGet(int wheel, int colliderInstanceId, out SurfaceProfile profile); // hit when same collider as last step
        public void Store(int wheel, int colliderInstanceId, SurfaceProfile profile);      // profile may be null (= default ground)
        public void Clear(int wheel);                                                      // wheel airborne
    }
}

// LV-02b — Assets/_Convoy/Scripts/Vehicle/SurfaceTag.cs
[RequireComponent(typeof(Collider))] [DisallowMultipleComponent]
public sealed class SurfaceTag : MonoBehaviour
{
    [SerializeField] private SurfaceProfile _profile;
    public SurfaceProfile Profile => _profile;
    // Must sit on the same GameObject as the collider the suspension ray hits (hit.collider). Ground raycasts ignore triggers,
    // so the tagged collider is solid: a mud patch is a thin solid box/mesh flush with (≤ 3 cm above) the ground.
}
```

### `VehicleController` edits (LV-02b) — the only allowed changes
Applied on top of D-01b (`mods` = `HandlingModifiers`) and Q-01b (counters).
1. Field `private WheelSurfaceCache _surfaces;` created in `Awake` with `_wheels.Length`.
2. Helper `private SurfaceModifiers ResolveSurface(int wheel, Collider collider)`: `id = collider.GetInstanceID()`; cache hit → `SurfaceModifiers.From(profile)`; miss → `collider.TryGetComponent(out SurfaceTag tag)`, store `tag ? tag.Profile : null`.
3. Wheel loop: airborne branch → `_surfaces.Clear(i)`; after `grounded++` → `SurfaceModifiers surface = ResolveSurface(i, hit.collider);` and count `if (!surface.IsDefault) { surfaceWheels++; surfaceKind = surface.Kind; }`.
4. Drive: forward drive uses a per-wheel factor `wheelDriveFactor = drive >= 0f ? VehicleMath.DriveFactor(forwardSpeed, _config.topSpeed * mods.TopSpeed * surface.TopSpeed + (boosting ? _config.boostTopSpeedBonus : 0f)) : driveFactor;` and `longitudinal += drive * _config.engineForce * mods.EngineForce * surface.DriveForce * wheelDriveFactor / drivenCount;`
5. Rolling resistance: `* surface.RollingResistance`. Grip: `float grip = (...) * mods.Grip * surface.LateralGrip;` (handbrake multiplier after, unchanged).
6. Friction circle: `_config.tireFriction * surface.Friction * normalForce`.
7. `WriteState(grounded, sliding, surfaceWheels, surfaceKind)`; the recovery call passes `0, SurfaceKind.Default`. `VehicleState` gains `public int SurfaceWheels; public SurfaceKind Surface;` (Default when no wheel on a tagged surface).
Each edit commented `// LV-02: surface multiplier (1.0 off-surface)`. Boost push, steering, suspension, downforce, air control untouched.

## Acceptance criteria
1. EditMode green. `SurfaceModifiers.None` fields are exactly `1f` (`Assert.AreEqual(1f, x)`); `From(null)` == None; NaN field → 1f; `WheelSurfaceCache` hit/miss/clear per wheel; `Is.Not.AllocatingGCMemory()` on `From` and cache calls.
2. **Regression (mandatory, README rule):** D-01b's `JackalHandlingRegressionTests` pass unchanged (0–100 km/h 3.4 s ± 0.3; equal to the no-damage run within 0.02 s).
3. PlayMode `SurfaceZoneTests` (flat 2 km ground, Jackal via `AssetDatabase`, full throttle via `IPilotCommandReceiver`): (a) ground tagged with a profile whose multipliers are all 1 → 0–100 km/h time equals untagged ground within 0.02 s; (b) whole run on default mud → speed at 6 s between 0.40× and 0.75× of the untagged run; `VehicleState.SurfaceWheels == 4` and `Surface == ToxicMud` while on it; (c) 6 s full throttle + boost held on mud → faster than (b) by ≥ 15 % (nitro unaffected); (d) leaving the patch → `SurfaceWheels == 0` within one step.
4. Manual (Gabriel, after LV-02c) in `Sandbox`: entering `MudPatch_Test` at speed clearly drags the car down and makes it slide wider in turns; one wheel in mud pulls the car slightly to that side (per-wheel effect, expected); outside the patch the car feels unchanged; nitro gets you out.
5. Perf: `VehicleController.FixedUpdate` 0 B GC (Profiler) and ≤ +0.01 ms vs before on the Sandbox (4 wheels).

## Perf constraints
`TryGetComponent` only on a cache miss (wheel changes collider); `GetInstanceID` and `From` are allocation-free; no per-step `GetComponent`.

## Risks
- Overlapping ground and mud colliders at the same height make the hit ambiguous → mud top surface 0.03 m above ground (prefab) or a sunken riverbed (LV-03 brief).
- One-sided mud yanks the car (per-wheel drive/grip asymmetry) — realistic but may feel unfair; tune `driveForceMultiplier` up before changing the model.
- Editing `VehicleController` again (third task in sequence) → strict edit list + both PlayMode suites; reviewer diffs line by line.
- Multiplying many floats changes nothing off-surface only if every multiplier is exactly `1f`; reviewer rejects any reordering of the existing arithmetic (e.g. hoisting `driveFactor`) that is not a pure `× 1f` insertion.
