# Spec LV-03 — Sprint_02 "Toxic Wastes" biome (fork, chasm, Rammer gate, mud, uplink)

> **Design brief required from Narrative & Game Designer** before LV-03b starts. LV-03a (pure layout maths) may start without it.

## Design brief — required inputs (ND fills `docs/design/LV-03_ToxicWastes_brief.md`, Gabriel approves)
The builder transcribes these numbers into code (`ToxicWastesLayoutDefaults`); nothing is invented by agents. Units: metres, seconds, degrees; positions in a top-down X/Z grid with the start at (0, 0) and +Z = initial heading.

| # | Input | Constraint / default the brief must respect |
|---|---|---|
| 1 | **Fantasy & readability:** palette (3–4 colours), fog colour/density, 2–3 landmarks, whether the Monolith is visible from the start | URP fog + primitives only (D-021: no paid assets) |
| 2 | **Target times:** Monolith (author), Gold, Silver, Bronze; expected average speed | run 90–180 s incl. ~5 s uplink (D-022); 0 < Monolith < Gold < Silver < Bronze |
| 3 | **Main route** (the safe line, always drivable): ordered nodes `(x, y, z, width)` | width 8–16 m; slope ≤ 20°; node spacing ≥ 20 m; main length ≈ target time × avg speed |
| 4 | **Checkpoints:** distances along the main route | 4–6; ~every 20–30 s; **never inside a section a shortcut bypasses** (ordered checkpoints would block shortcut takers) |
| 5 | **Chasm fork:** branch from/to distances on main, branch nodes, gap length, kicker ramp angle, landing height delta, time saved vs main | min clear speed (computed) between 15 m/s and 0.8 × Jackal top speed (32 m/s); failing = fall into a 12 m pit → manual reset to last checkpoint |
| 6 | **Rammer gate shortcut:** branch from/to distances, gate position, straight run-up length, time saved | run-up ≥ 120 m with ≤ 15° heading change; say whether it is meant to need nitro (e.g. placed after mud or a slow corner) |
| 7 | **Toxic mud:** footprints (route + distance + length + width), mandatory or optional, multiplier overrides if any | default profile −40 % (LV-02); mud is solid ground, not water |
| 8 | **Boundaries & props:** soft (rocks you bump) vs hard (cliff) edges, prop density per 100 m, wrecks | boundary rocks generated along the outer edges; no invisible walls |
| 9 | **Monolith & uplink:** final straight length, zone size, hold time if not 4 s | zone fits inside the terrain; uplink after the last checkpoint |
| 10 | **Discoverability:** how each shortcut is signposted (orange Rammer marks, sightline to the chasm landing, tyre tracks), what a first-timer sees | — |
| 11 | **Done for ND:** the playtest result that accepts the level | e.g. 3 of 3 testers find ≥ 1 shortcut by attempt 3; median first-run time ≤ Bronze |

## Objective
Generate the second biome sprint (Toxic Wastes, D-022) from versioned, re-runnable editor scripts driven by a layout data asset, so the level can be rebuilt after ND's playtest tweaks without anyone hand-editing scene YAML. The level teaches the retry loop: a safe main line plus two discoverable shortcuts (chasm jump, Rammer gate), a toxic-mud section, and the Monolith uplink.

## Scope
`BiomeLayout` (+ structs), `LayoutMath`, `HeightfieldMath`, `LayoutValidator` (Level module); `ToxicWastesLayoutDefaults`; geometry generator; race-wiring script; `Sprint_02` in Build Settings.

## Out of scope
AI rivals in Sprint_02 (run A-01c's `ApplyToScene` later; follow-up task), chasm bridge terminal (D-021, post-M1), auto-reset kill volumes (pit = manual reset), lighting bake, final art/textures, minimap.

## Public interfaces
```csharp
// LV-03a — Assets/_Convoy/Scripts/Level/BiomeLayout.cs
namespace Convoy.Level
{
    [Serializable] public struct RouteNode { public Vector3 position; [Min(4f)] public float width; }
    [Serializable] public struct BranchSpec
    {
        public string name;                // "chasm", "rammer"
        public float fromDistance, toDistance;   // along the main route; the branch leaves/rejoins main there
        public RouteNode[] nodes;          // interior nodes only; endpoints are the main-route points at from/to
    }
    public enum FeatureKind : byte { Checkpoint = 0, RammerGate = 1, Chasm = 2, Mud = 3 }
    [Serializable] public struct FeatureSpec
    {
        public FeatureKind kind;
        public int branch;                 // −1 = main route, else index into branches
        public float distance;             // along that route (start of the feature)
        public float length;               // chasm gap / mud length (m); unused for checkpoints/gates
        public float width;                // 0 = route width
        public float rampAngleDeg;         // chasm kicker angle
        public float heightDelta;          // chasm landing height − take-off height (negative = downhill landing)
    }

    [CreateAssetMenu(fileName = "BiomeLayout", menuName = "Convoy/Biome Layout")]
    public sealed class BiomeLayout : ScriptableObject
    {
        public string sprintId = "toxic_wastes";
        public string sceneName = "Sprint_02";
        public Vector2 terrainSize = new Vector2(1000f, 1000f);
        public float terrainMaxHeight = 80f, baseHeight = 20f;
        public float duneAmplitude = 4f, duneFrequency = 0.012f; public int seed = 2;
        public float shoulderWidth = 6f, roadSegmentSpacing = 3.7f;   // 3.7 m = Sprint_01 Road_N spacing (A-01c racing-line source)
        public float chasmDepth = 12f, boundaryRockSpacing = 9f;
        public float uplinkFinalStraight = 60f;
        public RouteNode[] main = Array.Empty<RouteNode>();
        public BranchSpec[] branches = Array.Empty<BranchSpec>();
        public FeatureSpec[] features = Array.Empty<FeatureSpec>();
    }

    // LV-03a — Assets/_Convoy/Scripts/Level/LayoutMath.cs (pure)
    public static class LayoutMath
    {
        public static float Length(IReadOnlyList<RouteNode> nodes);
        public static void PoseAt(IReadOnlyList<RouteNode> nodes, float distance, out Vector3 position, out Vector3 forward, out float width); // clamps
        public static int Resample(IReadOnlyList<RouteNode> nodes, float spacing, List<Vector3> into);
        public static float MaxHeadingChange(IReadOnlyList<RouteNode> nodes, float fromDistance, float toDistance);   // degrees
        /// Ballistic minimum take-off speed to clear `gap` from a kicker at `rampAngleDeg` landing `heightDelta` higher:
        /// v² = g·gap² / (2·cos²θ·(gap·tanθ − heightDelta)); +∞ when gap·tanθ ≤ heightDelta.
        public static float MinSpeedToClear(float gap, float rampAngleDeg, float heightDelta, float gravity = 9.81f);
    }

    // LV-03a — Assets/_Convoy/Scripts/Level/HeightfieldMath.cs (pure)
    public static class HeightfieldMath
    {
        /// World height at (x, z): Perlin dunes outside corridors; flattened to the nearest route height inside width/2 + shoulder
        /// (smoothstep blend over the shoulder); chasm footprints lowered by chasmDepth. Deterministic for a given layout.
        public static float HeightAt(BiomeLayout layout, float x, float z);
        public static void Fill(BiomeLayout layout, int resolution, float[,] heights01);   // normalised for TerrainData.SetHeights
    }

    // LV-03a — Assets/_Convoy/Scripts/Level/LayoutValidator.cs (pure)
    public static class LayoutValidator
    {
        /// Appends human-readable errors; returns error count. vehicleTopSpeedMps passed in (Level does not reference Vehicle).
        public static int Validate(BiomeLayout layout, float vehicleTopSpeedMps, float expectedAvgSpeedMps, List<string> errors);
    }
}
```
**Validation rules (each a test case):** ≥ 2 main nodes; widths 8–16; checkpoints only on main (`branch == −1`), 4–6 of them, strictly increasing, none inside any `[fromDistance, toDistance]` of a branch; branch `from < to`, inside main length; chasm `MinSpeedToClear` in [15, 0.8 × top speed]; rammer gate on a branch with main run-up ≥ 120 m before `fromDistance` and `MaxHeadingChange` ≤ 15° over it; mud inside its route; `uplinkFinalStraight` after the last checkpoint; estimated time `mainLength / expectedAvgSpeed` within 85–175 s (leaves room for the uplink hold); route inside terrain bounds with ≥ 30 m margin.

## Generated content (LV-03b) — `Convoy/Integration/LV-03 Build Sprint_02 Geometry`
File `Assets/_Convoy/Editor/Integration/LV03_BuildSprint02Geometry.cs` + `ToxicWastesLayoutDefaults.cs` (brief numbers in code).
1. Create `Config/Level/ToxicWastes_Layout.asset` from `ToxicWastesLayoutDefaults.Create()` if missing (after that, ND tunes the asset in the Inspector and re-runs). Run `LayoutValidator`; any error → log all and **abort** (no scene change).
2. Create `Scenes/Sprint_02.unity` (`NewSceneSetup.DefaultGameObjects`) if missing; else open it.
3. If a `[Generated]` root exists: rename to `[Generated]_superseded_<yyyyMMdd-HHmmss>` and `SetActive(false)` (**never delete**; a human removes superseded roots). Build a new `[Generated]` root:
   - `Terrain`: new `TerrainData` asset `Scenes/Sprint_02/Sprint_02_TerrainData[_n].asset` (never overwrite; numeric suffix), heightmap 513², `HeightfieldMath.Fill`, one `TerrainLayer` from a generated 4 × 4 PNG in the brief's ground colour.
   - `Road/Road_<n>`: main route resampled at `roadSegmentSpacing` → thin boxes (width × 0.1 × spacing + 0.2), top 0.02 m above the corridor, contiguous `n` in driving order (A-01c compatible). Branches: `Road/RoadAlt_<branch>_<n>`; chasm gaps leave segments out.
   - `Chasm_<i>`: kicker wedge (box rotated by `rampAngleDeg`, length 8 m) before the gap; landing ramp (12 m, 8°) after it; terrain already carved by `HeightfieldMath`.
   - `Mud_<i>`: `MudPatch.prefab` (LV-02c) instances tiled along the route over `length × width`, top 0.03 m above road.
   - `RammerGate_<i>`: `RammerGate.prefab` (LV-01c) at the branch mouth, facing along the branch.
   - `Boundary/Rock_<n>`: boxes along both outer corridor edges every `boundaryRockSpacing` (deterministic jitter, `seed`), skipping branch mouths.
   - `StartLine` marker at main distance 0.
4. Mark dirty, save, log a summary (counts per category, main length, estimated time, chasm min speed). Running twice with an unchanged layout produces an identical `[Generated]` hierarchy (names/transforms) in a new root and the superseded copy; the menu `LV-03 Check Sprint_02 (dry run)` validates and prints the summary **without** touching the scene.

## Acceptance criteria
1. EditMode green. `MinSpeedToClear(20 m, 20°, 0)` = 17.5 ± 0.1 m/s (hand-computed in the test comment); `heightDelta` ≥ gap·tanθ → +∞; `PoseAt` at node distances returns the nodes; `HeightAt` deterministic and equal to the route height (± 0.01) on the centreline, `baseHeight − chasmDepth`-relative inside a chasm footprint.
2. Every validation rule has a failing and a passing test case; `ToxicWastesLayoutDefaults` passes validation with Jackal top speed 40 m/s.
3. LV-03b: generator on a clean checkout creates the scene; second run → previous root superseded + inactive, new root identical in names/transform values (orchestrator compares the logged summary); dry-run menu changes nothing (`git status` clean).
4. LV-03c: run twice → second run logs 0 changes; `Sprint_01.unity` unchanged; Sprint_02 is in Build Settings.
5. Manual (Gabriel + ND): Play `Sprint_02` → keyboard driving works; HUD, splits, ghost, uplink appear; a clean main-line run finishes within the brief's Bronze time; the chasm is cleared at the brief's speed with nitro and failing it requires R; the Rammer gate breaks at ≥ 80 km/h after the brief's run-up; mud slows noticeably; checkpoints cannot be skipped by either shortcut; frame time ≤ 8 ms on Gabriel's PC (Profiler, 1080p).
6. ND acceptance (brief item 11) recorded in the next playtest report.

## Risks
- **Biggest spec in the batch**; split three ways and gated on the brief to keep each PR < 20 min review.
- Road boxes over a carved terrain can leave seams/steps on slopes → slope ≤ 20° and 0.2 m segment overlap; check in AC 5.
- Falling into the chasm pit needs a manual reset (no kill volume in M1) → if testers get stuck, add a `RecoveryVolume` follow-up (V-02 extension, not in this task).
- Copying Monolith/Global Volume from Sprint_01 breaks the model-prefab link (values copied); acceptable for greybox.
- Superseded roots accumulate on re-runs; a human deletes them (CLAUDE.md delete rule).
