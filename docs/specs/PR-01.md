# Spec PR-01 — Biome progression by medals

- **Human owner/reviewer:** Gabriel (+ ND for unlock thresholds) · **Builder agent:** ui-input-engineer · **Architecture:** ADR-001, ADR-006 §§ 1, 3, 7 (proposes D-028)
- **Split:** **PR-01a** `SprintCatalog` + pure `ProgressionRules` + EditMode tests · **PR-01b** `SprintController` catalog/load API, `SprintSelectOverlay`, unlock line on the result screen · **PR-01c** integration: catalog asset wired into both sprints + editor save tools (executed by the orchestrator)

## Objective
Medals unlock the next biome (D-022 retention driver, no economy): Toxic Wastes (`Sprint_02`) unlocks with **Silver** in Red Canyon (`Sprint_01`). A minimal sprint-select overlay, opened from the result screen, lists the sprints with best time, best medal and lock reason, and loads an unlocked one. Unlocks are derived from saved medals, never stored (D-024/D-028).

## Scope
`SprintCatalog`, `ProgressionRules`; `SprintController` catalog API + `LoadSprint`; `SprintSelectOverlay`; result-screen unlock line and select prompt; catalog asset; editor menu "Reveal save folder" / "Backup and reset save".

## Out of scope
Main menu / title scene, vehicle-class unlocks (post-M1, same rules), currencies/economy/MTX, cloud saves, opening the overlay during a run or in `Ready` (keys would also drive the car), achievements.

## Public interfaces
```csharp
// PR-01a — Assets/_Convoy/Scripts/Race/SprintCatalog.cs
namespace Convoy.Race
{
    [CreateAssetMenu(fileName = "SprintCatalog", menuName = "Convoy/Sprint Catalog")]
    public sealed class SprintCatalog : ScriptableObject
    {
        [Serializable] public struct Entry
        {
            public SprintDefinition sprint;
            [Tooltip("Null = unlocked from the start.")] public SprintDefinition requires;
            public Medal requiredMedal;
        }
        [SerializeField] private Entry[] _entries = Array.Empty<Entry>();
        public int Count { get; }
        public Entry Get(int index);
        public int IndexOf(SprintDefinition sprint);        // −1 if absent
        // OnValidate: warn on duplicate sprintIds, an entry requiring itself, or a requirement not in the catalog.
    }

    // PR-01a — Assets/_Convoy/Scripts/Race/ProgressionRules.cs (pure)
    public static class ProgressionRules
    {
        /// max(stored bestMedal, MedalRules.Evaluate(bestTime, def.medals)) — a medal is never lost, and threshold edits are honoured.
        public static Medal BestMedal(SaveData save, SprintDefinition sprint);
        public static bool IsUnlocked(in SprintCatalog.Entry entry, SaveData save);  // requires == null → true
        /// Entries whose requirement is `finished` and whose requiredMedal lies in (previousBest, newBest]. Fills `into` (cleared first), returns count.
        public static int CollectNewlyUnlocked(SprintCatalog catalog, SprintDefinition finished, Medal previousBest, Medal newBest, List<SprintDefinition> into);
        /// "SILVER IN RED CANYON" style lock reason for the overlay (allocates; called on open only).
        public static string LockReason(in SprintCatalog.Entry entry);
    }
}

// PR-01b — Assets/_Convoy/Scripts/Race/SprintController.cs (edits listed below only)
public sealed class SprintController
{
    [SerializeField] private SprintCatalog _catalog;          // null → no sprint select (overlay hidden, prompt hidden)
    public SprintCatalog Catalog { get; }
    public bool IsUnlocked(int catalogIndex);
    public Medal GetBestMedal(SprintDefinition sprint);
    public float GetBestTime(SprintDefinition sprint);        // 0 = none
    public IReadOnlyList<SprintDefinition> NewlyUnlocked { get; } // filled at finish (preallocated List, cleared per run)
    /// Flow request (ADR-001 accepted exception): re-checks IsUnlocked and Application.CanStreamedLevelBeLoaded(sceneName);
    /// writes the save; SceneManager.LoadScene. Returns false (and logs) when locked or not in Build Settings.
    public bool LoadSprint(int catalogIndex);
}

// PR-01b — Assets/_Convoy/Scripts/Presentation/SprintSelectOverlay.cs
namespace Convoy.Presentation
{
    /// Self-bootstraps next to a SprintController that has a Catalog. Opens only on the result screen (Phase == Finished)
    /// with Tab / Gamepad.buttonNorth; Up/Down or W/S or d-pad select; Enter / buttonSouth loads; Esc / buttonEast closes.
    /// Rows: display name · best time · medal (colour from SprintHudText) · lock reason in grey. Strings built on open only.
    [AddComponentMenu("")] public sealed class SprintSelectOverlay : MonoBehaviour { public bool IsOpen { get; } }
}
```

### `SprintController` edits (PR-01b) — the only allowed changes
1. `_catalog` field + the members above; `private readonly List<SprintDefinition> _newlyUnlocked = new List<SprintDefinition>(4);`
2. `CompleteFinish()` (RT-01b version): after `RecordFinish`, if `_catalog != null && _definition != null` → `ProgressionRules.CollectNewlyUnlocked(_catalog, _definition, LastOutcome.PreviousBestMedal, LastOutcome.BestMedal, _newlyUnlocked)` **before** `Finished?.Invoke()`.
3. `LoadSprint` as specified. Each edit commented `// PR-01: …`.

### `SprintHud` edits (PR-01b) — the only allowed changes
1. Result screen: one Accent line `TOXIC WASTES UNLOCKED` per `NewlyUnlocked` entry (max 2 shown).
2. Prompt line gains `·  TAB / Y  sprint select` when `Catalog != null`.
3. `Update`: if a `SprintSelectOverlay` on the same GameObject `IsOpen`, ignore Enter/Start (the overlay owns them).

## PR-01c integration script — `Convoy/Integration/PR-01 Progression Setup`
1. Create the catalog asset if missing (looks up both definitions by `sprintId`; aborts with an error if Toxic Wastes is missing).
2. `ApplyToScene(string scenePath)` (D-030) for `Sprint_01` and `Sprint_02`: assign `_catalog` on the `SprintController` if empty. Save, log, idempotent, never deletes.
3. `SaveTools.cs` (editor menu, not an integration step): `Convoy/Save/Reveal save folder` (`EditorUtility.RevealInFinder(Application.persistentDataPath)`) and `Convoy/Save/Backup and reset save` (renames `convoy_save.json` and `ghosts/` with a `.backup-<yyyyMMdd-HHmmss>` suffix; confirmation dialog; never deletes).

## Acceptance criteria
1. EditMode green. Empty save → Red Canyon unlocked, Toxic Wastes locked; Bronze → still locked; Silver → unlocked; Gold → unlocked. `CollectNewlyUnlocked(prev Bronze → new Gold)` returns Toxic Wastes once; `(Silver → Gold)` returns none; `BestMedal` honours a lowered threshold (stored Bronze, bestTime now under Silver → Silver).
2. `LoadSprint` on a locked entry returns false and does not load (PlayMode-free: tested through `IsUnlocked` + a code path guard; manual for the scene load).
3. Manual (Gabriel, after PR-01c, with "Backup and reset save" first): finish Red Canyon slower than Silver → result screen has no unlock; overlay shows Toxic Wastes locked with "SILVER IN RED CANYON"; finish with Silver → "TOXIC WASTES UNLOCKED"; Tab → select → Enter loads `Sprint_02`; from Sprint_02's result screen Red Canyon can be loaded back; quitting and relaunching keeps the unlock; the backup files exist after reset.
4. Perf: no allocation in `SprintController.FixedUpdate`; overlay allocates only when opened.

## Perf constraints
Catalog ≤ 10 entries, linear scans on finish/open only. No per-frame `Resources.Load`/`FindObjectOfType`.

## Risks
- Overlay only on the result screen: a player in `Sprint_02` who wants to go back must finish (or quick-restart, then finish) first → acceptable for M1; a title/hub scene is a separate task if playtests ask (open question).
- Silver threshold depends on RT-01's provisional medal times; if Silver is too hard, the second biome is never seen → playtest check, tune data only.
- Editor and build share the save → "Backup and reset save" before every playtest session (protocol note for ND).
