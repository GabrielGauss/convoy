# Spec RT-01 — Splits vs personal best, medal times, local save

- **Human owner/reviewer:** Gabriel (retry feel, medal times) · **Builder agent:** ui-input-engineer · **Architecture:** ADR-001, ADR-006 §§ 1, 3, 6, 7 (proposes D-024, D-028, D-029)
- **Split:** **RT-01a** pure logic: splits in `SprintRun`, medals, `SprintDefinition`, save model + store · **RT-01b** `SprintController` wiring (save, PB, splits events, legacy migration, attempts, quick-restart request) · **RT-01c** `SprintHud`: live split deltas, medal target, result screen, quick-restart input · **RT-01d** integration: `RedCanyon_SprintDefinition` asset wired into `Sprint_01` (executed by the orchestrator)

## Objective
Give every run a reason to retry: per-checkpoint split times compared live against the personal-best run (green = ahead, red = behind), Bronze/Silver/Gold/**Monolith** (author) medal thresholds per biome, a result screen that shows the medal earned and the gap to the next one, and a quick restart from anywhere. Results persist locally in a versioned JSON file (D-024); no services.

## Scope
`SprintRun` splits; `Medal`, `MedalTimes`, `MedalRules`, `SprintDefinition`; `SaveData`, `SprintRecord`, `RunOutcome`, `SaveStore`, `ISaveFileSystem`, `DiskSaveFileSystem`; `SprintController` save/medal/split wiring + `RequestQuickRestart()`; `SprintHud` deltas/medals/result/quick restart; `Sprint_01` definition asset.

## Out of scope
Ghosts (RT-02 — but RT-01b exposes what it needs), unlocks/sprint select (PR-01), leaderboards/online anything, per-segment "theoretical best", localisation, UI Toolkit rebuild (IMGUI kept per D-013).

// RT-01a — Assets/_Convoy/Scripts/Race/Medals.cs
namespace Convoy.Race
{
    public enum Medal : byte { None = 0, Bronze = 1, Silver = 2, Gold = 3, Monolith = 4 }

    [Serializable] public struct MedalTimes { public float bronze, silver, gold, monolith; }   // seconds; lowerCamel = Inspector/JSON style of VehicleConfig

    public static class MedalRules
    {
        public static int ToHundredths(float seconds);                       // same rounding as SprintRun.FormatTime (away from zero)
        public static bool IsValid(in MedalTimes t);                         // 0 < monolith < gold < silver < bronze
        public static Medal Evaluate(float time, in MedalTimes t);           // inclusive, compared in hundredths; time <= 0 or NaN → None
        public static float Threshold(Medal m, in MedalTimes t);             // None → 0
        /// Best medal still reachable when `elapsed` has already run (HUD target while driving): highest medal with threshold ≥ elapsed.
        public static bool TryGetBestReachable(float elapsed, in MedalTimes t, out Medal medal, out float threshold);
        /// Next medal above `earned` and the seconds missing to it (result screen). false when earned == Monolith.
        public static bool TryGetNext(float time, in MedalTimes t, out Medal next, out float secondsShort);
    }
}

public interface ISaveFileSystem
{

    public void Write();
    public static string ToJson(SaveData data);                      // JsonUtility, prettyPrint true
    public static SaveLoadResult TryParse(string json, out SaveData data);
    public void RecordAttempt(string sprintId);
    public RunOutcome RecordFinish(string sprintId, float time, float[] splits, int splitCount, in MedalTimes medals, string vehicle, string buildVersion);

**`RecordFinish` rule:** `finishes++`; `medal = Evaluate(time)`; `bestMedal = max(stored, medal)` (a medal is never lost); new best iff `bestTime <= 0 || time < bestTime` → `bestTime = time`, `bestSplits = splits[0..splitCount)` (allocation allowed: finish only), `vehicle`, `buildVersion` updated. Returns the filled `RunOutcome`.

**HUD behaviour (RT-01c):**
- Top panel line 2: `CHECKPOINT n / N` + `PB mm:ss.ff`; new line 3: best reachable medal target `GOLD 01:40.00` in medal colour (`TryGetBestReachable(run.Elapsed)`), hidden without a definition.
- On `CheckpointPassed(i)`: for 2.5 s show `SPLIT i+1   -1.23` under the panel, green if ahead, red if behind, white split time if no PB split. Strings formatted **once** per event.
- Result screen: time, medal name in its colour (or "NO MEDAL"), `NEW BEST -1.23` or `PB 01:42.10  (+0.85)`, `SILVER IN 2.31 s` when a next medal exists, prompt line unchanged plus `HOLD BACKSPACE / BACK — quick restart` hint on the running HUD (small, bottom-left).
- Quick restart: Backspace or `Gamepad.selectButton` held 0.4 s (while not Finished) → `_sprint.RequestQuickRestart()`; small fill bar while holding. Reads devices directly like today's Enter/Start (F-03 keeps SprintHud on direct reads, F-03 spec § Bindings).

## Acceptance criteria
1. EditMode green. `SprintRun`: splits recorded only for accepted checkpoints; `CopySplits` returns `SplitCount`; existing `SprintRunTests` unchanged and green.
2. `MedalRules.Evaluate`: time exactly equal to Gold threshold (100.00) → Gold; 100.004 (rounds to 100.00) → Gold; 100.006 → Silver; 0/NaN → None; slower than Bronze → None. `TryGetNext(101.5)` → Gold, 1.50 s.
3. `SaveStore`: JSON round-trip preserves every field; corrupt text and `version: 2` are moved aside (fake FS records the rename) and `Data` is empty; `RecordFinish` never lowers `bestMedal`; slower run keeps old splits; legacy import happens once only.
4. PlayMode `SprintSaveTests` (`SaveRootOverride` = temp dir, 2 checkpoint gates on code-built ground, legacy finish gate): two runs → `convoy_save.json` exists with `finishes = 2`, `attempts ≥ 2`, `bestSplits.Length = 2`; second slower run → `IsNewBest == false`, `DeltaToPreviousBest > 0`.
5. Legacy safety: with `_definition` unset, `Sprint_01` behaves exactly as before (PlayerPrefs best, same HUD).
6. Manual (Gabriel, after RT-01d) in `Sprint_01`: first finish shows a medal and writes `%USERPROFILE%\AppData\LocalLow\<company>\<product>\convoy_save.json`; second run shows green/red split deltas at every checkpoint; medal target line switches tier when the clock passes a threshold; quick restart (hold Backspace) works mid-run and **control returns ≤ 2.0 s** after release (stopwatch, 3 tries, D-029); old PlayerPrefs best appears as PB on first launch.
7. Perf: `SprintController.FixedUpdate` 0 B GC; `SprintHud` allocates only when displayed text changes (timer ≤ 1 string per displayed hundredth; delta/medal strings once per event). Save IO only at finish/restart.

## Risks
- `JsonUtility` cannot serialise dictionaries/properties → plain fields + `List<>` only (enforced by the round-trip test).
- Editor and builds share `persistentDataPath` → developer PBs leak into playtest builds; PR-01c adds "Backup and reset" menu; testers start from a clean profile (playtest protocol).
- Medal times are placeholders until Gabriel records author times; wrong numbers make medals trivial or impossible → checked in the first playtest.
- `SprintController` grows; strict edit list keeps the diff reviewable.
