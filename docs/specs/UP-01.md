# Spec UP-01 — Monolith uplink finale

- **Human owner/reviewer:** Gabriel (feel) + Narrative & Game Designer (hold length) · **Builder agent:** ai-engineer · **Architecture:** ADR-001, ADR-006 § 5 (proposes D-025)
- **Split:** **UP-01a** pure hold logic + config SO + EditMode tests · **UP-01b** `UplinkZone`, `SprintController` hook, `UplinkHud`, PlayMode test · **UP-01c** integration script: uplink zone + config asset in `Sprint_01` (executed by the orchestrator)

## Objective
Replace the instant finish line with a scaled-down Payload uplink (D-021 → D-022): after every checkpoint is passed, the run finishes only when the vehicle stays inside the Monolith zone for `holdSeconds` (default 4 s). A progress ring shows the hold; leaving the zone resets it. The clock keeps running during the hold, so braking into the zone is part of the skill. Scenes without a zone keep today's instant finish, so `Sprint_01` never breaks.

## Scope
`UplinkConfig`, `UplinkHold`, `UplinkRingMath` (pure); `UplinkZone`; `SprintController` uplink edits; `UplinkHud`; PlayMode uplink test; `Sprint_01` integration.

## Out of scope
Uplink audio (later AUD task), contested uplinks / rivals in the zone (R-01), payload vehicles, camera moves at the finish, result screen text (RT-01c), a new `SprintPhase` value (ADR-006 § 7: "uplinking" is derived).

## Public interfaces
```csharp
// UP-01a — Assets/_Convoy/Scripts/Race/UplinkConfig.cs
namespace Convoy.Race
{
    public enum UplinkExitBehaviour : byte { Reset = 0, Decay = 1 }

    [CreateAssetMenu(fileName = "UplinkConfig", menuName = "Convoy/Uplink Config")]
    public sealed class UplinkConfig : ScriptableObject
    {
        [Tooltip("Seconds the vehicle must stay inside the Monolith zone to finish.")]
        [Min(0.1f)] public float holdSeconds = 4f;
        [Tooltip("Above this speed the hold does not advance, km/h. 0 = no limit.")]
        [Min(0f)] public float maxHoldSpeedKmh = 0f;
        [Tooltip("What happens to progress when the vehicle leaves the zone (or is too fast).")]
        public UplinkExitBehaviour exitBehaviour = UplinkExitBehaviour.Reset;
        [Tooltip("Decay mode only: held seconds lost per second outside.")]
        [Min(0f)] public float decayPerSecond = 2f;
    }
}

// UP-01a — Assets/_Convoy/Scripts/Race/UplinkHold.cs   (pure, no Unity calls besides reading the SO)
namespace Convoy.Race
{
    public sealed class UplinkHold
    {
        public const float CompletionEpsilon = 1e-4f;    // 200 × 0.02f accumulates to 3.9999…; must still complete on step 200
        public UplinkHold(UplinkConfig config);           // throws ArgumentNullException on null
        public float HeldSeconds { get; }
        public float Progress01 { get; }                  // HeldSeconds / holdSeconds, clamped [0,1]
        public bool Inside { get; }                       // inside AND under the speed limit on the last Tick
        public bool Complete { get; }
        /// Advance one physics step. Returns true only on the step the hold completes; false afterwards.
        public bool Tick(float deltaTime, bool insideZone, float speedMps);
        public void Reset();
    }

    public static class UplinkRingMath
    {
        /// Number of lit ring segments for a progress value: ceil(progress01 × segmentCount), 0 at 0, clamped, NaN → 0.
        public static int LitSegments(float progress01, int segmentCount);
    }
}
```
**`Tick` rule:** `dt = max(0, dt)` (NaN → 0). `ok = insideZone && (maxHoldSpeedKmh <= 0 || speedMps * 3.6f <= maxHoldSpeedKmh)`. If `Complete` → return false. If `ok`: `HeldSeconds += dt`; else `Reset` mode → `HeldSeconds = 0`, `Decay` mode → `HeldSeconds = max(0, HeldSeconds − decayPerSecond × dt)`. If `HeldSeconds >= holdSeconds − CompletionEpsilon` → `Complete = true`, `HeldSeconds = holdSeconds`, return true.

### `SprintController` edits (UP-01b) — the only allowed changes
1. Fields `_uplink`, `_uplinkConfig`, `private UplinkHold _hold;` + the three getters above.
2. `Awake`: if `_uplink != null && _uplinkConfig != null` → `_hold = new UplinkHold(_uplinkConfig)`; if exactly one of them is set → `Debug.LogError` and stay legacy (`_hold = null`).
3. `FixedUpdate` after `_run.Tick(...)`: if `_hold != null && _run.Phase == SprintPhase.Running && _run.AllCheckpointsPassed`: `inside = _uplink.Contains(_vehicle.State.Position)`; `if (_hold.Tick(Time.fixedDeltaTime, inside, _vehicle.State.Velocity.magnitude)) CompleteFinish();`
4. `OnGateEntered`: the finish branch becomes `if (_hold != null) return; CompleteFinish(); return;`.
5. Extract the existing finish body (TryFinish, PlayerPrefs best, `Finished?.Invoke()`) into `private void CompleteFinish()` — behaviour identical.
Each change carries a one-line comment `// UP-01: uplink finish (D-025)`. No other edits (RT-01b edits this file next).

## Acceptance criteria
1. EditMode green (new + existing). `UplinkHold` with `holdSeconds = 4`, `dt = 0.02f`: `Tick` returns true on exactly the 200th consecutive inside step, never before; `Complete` stays true and further `Tick`s return false.
2. Reset mode: 150 steps inside, 1 outside, → `HeldSeconds == 0`; Decay mode (2/s): 150 in, 25 out → `HeldSeconds ≈ 2.0 ± 0.001`. Speed limit 30 km/h: inside at 10 m/s doesn't advance.
3. Legacy safety: with `_uplink` unset, the PlayMode test's finish gate ends the run instantly exactly as before (test case `LegacyFinishGateStillFinishes`).
4. PlayMode `UplinkTests` (code-built flat ground, Jackal prefab via `AssetDatabase` under `#if UNITY_EDITOR`, `SprintController` configured on an inactive GameObject through `SerializedObject` then activated; 0 checkpoints): (a) drive 2 s, brake to a stop inside a 30 × 6 × 60 m zone → `Finished` fires 4.0–4.1 s after the vehicle first entered the zone; `run.Elapsed` at finish ≥ time-to-zone + 4.0 s. (b) zone that ends before the car stops → no `Finished` within 10 s.
5. Manual (Gabriel, after UP-01c) in `Sprint_01`: crossing between the pillars at speed no longer ends the run; stopping in the zone shows the ring filling and finishes after ~4 s; driving out mid-hold empties the ring; a V-02 reset during the hold empties it; HUD final time includes the hold; Q-01 CSV still written with `finished=1`.
6. Perf: `SprintController.FixedUpdate` and `UplinkHud.OnGUI` 0 B GC (percent label from a 101-entry string table built once; Profiler or `Is.Not.AllocatingGCMemory()` on `UplinkHold.Tick`).

## Risks
- Zone placement in `Sprint_01` (6 m past the pillars, 16 × 12 × 16 m) is a guess from the `Finish` gate pose; the Monolith mesh may overlap it → Gabriel checks in AC 5 and tunes `_halfExtents`/position in the Inspector (scene change by the orchestrator).
- 4 s may feel long on a 90 s sprint → `holdSeconds` is data; ND decides after the first playtest (open question).
- One-step latency (SprintController reads last tick's `VehicleState`) shifts finish by ≤ 20 ms; identical for every run, so PB comparisons are fair.
