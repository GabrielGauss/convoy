# Spec VH-01 — Sidecar motorbike (three-wheel class)

- **Human owner/reviewer:** Gabriel (feel) · **Builder agents:** vehicle-engineer (code + config), orchestrator (prefab) · **Architecture:** ADR-007 §2 (D-035, D-038)
- **Split:** **VH-01a** class plumbing: `VehicleClass`, `IVehicleClassSource`, `VehicleConfig.vehicleClass`, `SeatLayout`, `ClassTraction` + EditMode tests · **VH-01b** sidecar data + presentation: `Sidecar_VehicleConfig`, `Sidecar_DamageConfig`, `SidecarLeanVisual` · **VH-01c** integration: `VH01_SidecarSetup` builds `Sidecar.prefab` (greybox) and adds it to the class picker in `Sandbox`

## Objective
A second, very different vehicle on the **existing raycast controller** (D-004): three wheels (two in line + the sidecar wheel), 1–2 seats (Pilot + sidecar Gunner), the best acceleration and turning of the three classes, the most fragile, the worst in mud. No new physics model; lean is visual only.

## Scope
- **Core:** `public enum VehicleClass : byte { Sidecar = 0, Jackal = 1, Heavy = 2 }`; `public interface IVehicleClassSource { VehicleClass Class { get; } }`.
- **Vehicle:** `VehicleConfig.vehicleClass` (default `Jackal`, so existing assets keep working); `VehicleController : IVehicleClassSource` (returns config value); `ClassTraction` SO `{ VehicleClass cls; float frictionScale, driveScale, topSpeedScale; }[]` applied on top of `SurfaceProfile` modifiers where they are combined today (one multiply, 0 B GC).
- **Crew:** `SeatLayout` SO (`SeatId[] seats`); `VehicleSeats` gets `[SerializeField] SeatLayout _layout` (null = all three seats, today's behaviour); `Join`/`Assign` refuses seats not in the layout.
- **Presentation:** `SidecarLeanVisual` tilts the body mesh by lateral acceleration from `VehicleState` (max angle, smoothing in SO). Reads only.
- **Data:** `Sidecar_VehicleConfig` (3 wheels: front steers, rear driven, sidecar wheel not driven, wide offset for stability), `Sidecar_DamageConfig`, `Sidecar_SeatLayout` (Pilot, Gunner), `ClassTraction_Default` (sidecar mud ≈ 1.25× penalty, JACKAL 1.0, heavy ≈ 0.85).

## Out of scope
Two-wheel balance physics, lean affecting handling, sidecar weapons (WP-01), AI sidecar (AI-03), final model (art brief, D-033).

## Starting numbers (tuning targets, all in SO)
| | Sidecar | JACKAL (today) |
|---|---|---|
| mass | ~450 kg | 1200 kg |
| topSpeed | ~37 m/s | 40 m/s |
| 0–100 km/h | best of three (target ≤ JACKAL − 15 %) | baseline |
| maxSteerAngle | ~36° | 32° |
| maxHealth | ~60 | 100 |
| clear width needed | ≤ 2.0 m | ~2.2 m |
Sidecar passages are ≤ JACKAL track width + 0.2 m (ADR-007 §3); VH-01c reports the measured track widths of both classes.

## Acceptance criteria
1. **EditMode:** `ClassTraction` lookup + combine (identity for unknown class, 0 B GC); `SeatLayout` refuses an Engineer join on the sidecar and the join order skips it; `VehicleConfig.vehicleClass` defaults to `Jackal`.
2. **PlayMode:** JACKAL handling regression test unchanged (no behaviour change for JACKAL assets).
3. **Integration:** `VH01_SidecarSetup` idempotent; `Sidecar.prefab` drives in `Sandbox` and `TrackKit_Test`.
4. **Gabriel checklist:** feels stable at top speed (no tip-over on flat road at full steer above 25 m/s); out-accelerates and out-turns the JACKAL; loses to it on a long straight; mud hurts it more than the JACKAL; the lean reads as a bike, causes no nausea.
5. No `switch (vehicleClass)` in `Convoy.Vehicle` behaviour code (review checklist).
